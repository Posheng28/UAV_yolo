# 四軸首飛：鏈路驗證流程

> 這份是「怎麼確認每條鏈路真的通」的實作步驟。**每一關都有明確判定標準，沒過就別進下一關。**
> UI 的「任務檢查 → 🔗 鏈路自檢」會實測所有鏈路；本文件補上自檢**測不到**的實體確認。

架構（四軸首飛建議走這條，最簡單）：

```
Walksnail 相機(掛 C-20T) → VTX ──圖傳──→ VRX ──HDMI──→ 採集卡 ──USB──→ 筆電
Pixhawk 6C Mini TELEM1 ──SiK 數傳──────────────────────────────────→ 筆電
                                                    （讀 pose＋發 DO_REPOSITION＋雲台 ROI）
```

---

## 關卡 0：桌面（不通電螺旋槳，**先拆槳**）

### 0-1 影像鏈路
1. VRX → 採集卡 → 筆電接好，**關閉 OBS** 等佔用程式。
2. 設定頁 → 影像來源 = HDMI 採集卡 → 填採集卡名稱關鍵字 → **按「🎥 測試影像來源」**。
3. ✅ **判定**：回報實際解析度（應為 1920×1080）與 FPS ≥ 20。
   ❌ 失敗 → 換 USB 孔（要 USB3）、確認 fourcc=MJPG、確認沒被其他程式佔用。

### 0-2 相機校正（**測地精度的地基**）
1. 印棋盤格（預設 9×6 內角點），**用實際飛行的整條鏈路**（相機→VTX→VRX→採集卡）拍。
2. 相機校正頁 → 開始 → 不同角度/距離擷取 15~25 張 → 計算 → 儲存 → 重啟引擎。
3. ✅ **判定**：RMS < 1.0 px；自檢的「相機校正」轉為 ✅。
   ⚠️ 沒校正也能飛，但測地會有系統性誤差、畫面邊緣尤其差。

### 0-3 圖傳延遲（**沒量＝固定偏移**）
1. 手機開碼錶（顯示到 0.01 秒）放在相機前。
2. 同時截圖「地面站畫面」與「手機本身」，兩者時間差 = 總延遲。
3. 填入設定頁「圖傳延遲 ms」→ 儲存（**即時生效**，不用重啟）。
4. ✅ **判定**：自檢「圖傳延遲補償」轉為 ✅。數位圖傳通常 80~200 ms。

### 0-4 YOLO 權重
1. 把訓練好的 `best.pt` 複製到 `weights/best.pt` → 重啟引擎。
2. 對著真實車輛（或手機播放的車輛影片）測試。
3. ✅ **判定**：自檢「YOLO 偵測」顯示使用 weights/best.pt 且有偵測數。
   ⚠️ 一直抓不到 → 設定頁把 `detector.conf` 降到 0.3~0.4（即時生效）。

### 0-5 數傳鏈路
1. SiK 電台一端接 Pixhawk **TELEM1**、一端接筆電。
2. 設定頁填 COM 埠與鮑率 57600 → 重啟引擎。**QGC 若佔用同一埠要先關**。
3. ✅ **判定**：自檢「數傳遙測」✅，且儀表板「載具」卡的模式/高度/姿態**會即時跳動**。
   ❌ 收不到心跳 → 換 COM 埠、確認電台配對（兩顆燈都恆亮）。

### 0-6 雲台鏈路
1. C-20T UART 接 Pixhawk 空閒 TELEM；PX4 設 `MNT_MODE_IN=4`。
2. **先用 QGC 測**：地圖上「指向此處」→ 雲台應實際轉動。
3. ✅ **判定**：自檢「雲台」顯示「有收到姿態回報」。
   ⚠️ 無回報 → 測地會失敗或改用指令角推算（精度差）。

### 0-7 GPS（**必須到室外**）
- ✅ **判定**：自檢「GPS 品質」✅（fix=3、衛星 ≥8、水平精度 ≤5m）。
- 室內幾乎不可能達標，這關要移到室外做。

### 🚩 關卡 0 通過條件
**執行「🔗 鏈路自檢」→ 不通（❌）數為 0**。警告（⚠️）可接受但要知道代價。

## 關卡 1：拆槳通電測試（**螺旋槳務必拆掉**）

1. 飛機通電、拆槳、放在室外空曠處。
2. 執行鏈路自檢 → 應全綠（含 GPS、Home）。
3. **故障注入**（每項做完都要確認「不會產生指令、不會有致動器輸出」）：
   - 拔掉數傳 → 自檢「數傳遙測」轉 ❌、儀表板顯示斷線
   - 遮住相機 → 目標丟失、進 COAST → LOST
   - 未解鎖時嘗試開導引 → 應被閘門擋住（顯示「載具未 arm」「尚未離地」）
4. **接管演練**：解鎖（仍拆槳）→ 切 Hold → 開導引 → 撥模式開關離開 Hold
   → ✅ **判定**：UI 立即顯示「飛行員已接管」紅字並停止發送，**切回 Hold 也不自動恢復**。

---

## 關卡 2：低風險實飛

**條件**：空曠合法空域、風小、目視範圍內、RC 隨時可接管、關卡 0/1 全過。

1. 裝槳，飛行員手動起飛到安全高度（30~50m）。
2. 切 **Hold（AUTO.LOITER）**。
3. 執行鏈路自檢 → 全綠（此時「指令鏈路」應顯示閘門無阻擋）。
4. 地面放一台車（或請人開），確認：
   - 儀表板鎖定目標（框變綠、🔒）
   - 目標卡的**座標合理**（對照 QGC 地圖上的實際位置）
   - 速度估計合理、不確定度 < 5m
5. **確認以上都對，才按導引按鈕兩次啟用**。
6. 觀察：飛機朝目標移動、俯視圖藍點追紅點、「最後指令」持續更新。
7. 隨時可撥桿接管——這是最終防線。

### ⚠️ 實飛中要盯的三件事
- **未發送原因**清單（紅字才是問題；藍色 ⏱ 是正常節流）
- **目標不確定度**（持續變大 = 測地有問題，該接管）
- **數傳連線**（斷線會停止發送，但**已接受的指令仍會執行**）

## 附錄：自檢測不到、只能人工確認的

| 項目 | 怎麼確認 |
|---|---|
| 兩條電台沒插反 | 拔掉其中一條，看自檢哪一項變 ❌ |
| C-20T 回報角度慣例正確 | 雲台指向已知地標，比對 UI 座標與地圖 |
| 測地座標的絕對正確性 | 讓目標停在**已知 GPS 點**，比對 UI 顯示的座標 |
| 圖傳延遲值 | 碼錶法（見 0-3） |
| 螺旋槳、電池、機構 | 標準飛前檢查（見「任務檢查」清單） |
