# 訓練自己的目標偵測模型

> 起因：實測發現**現成模型都認不得室內玩具車**——原本的空拍模型 0/5 幀、
> COCO yolo26n 與 yolo11s 也是 0/5，而空拍模型還把鞋子誤判成 `Car 0.38`。
> 網路上的空拍車輛模型（VisDrone/UAVDT 等）全是**真車**訓練的，同樣無效。
> 玩具車的尺度與紋理不在任何既有分佈裡，**只能用自己場景的資料訓練**。

## 完整流程（約 40 分鐘）

### 1. 收集影像（2 分鐘）

```bash
python tools/collect_dataset.py --count 200
```

**必須先啟動地面站且為實機模式**。工具抓的是 `/frame_raw.jpg`（**無疊加層**）。

> ⚠️ **絕對不要用 `/frame.jpg` 收訓練資料**——那是操作畫面，帶有偵測框與狀態文字。
> 曾經誤用導致 112 張影像含「綠框＋Car 0.81」標記，那會讓模型學成
> 「看到綠框就是車」，越訓越錯且完全無法從指標察覺。

收集時要涵蓋：

| 面向 | 做法 |
|---|---|
| 位置 | 畫面中央與四個角落都走過 |
| 距離 | 相機高度 40cm ~ 1.5m 變化 |
| 朝向 | 車頭轉向各方向、也可斜放 |
| 干擾物 | 讓鞋子、箱子、手入鏡 |
| **負樣本** | **留 15~20 秒畫面裡完全沒有車** |

負樣本是治好誤判的關鍵——明確告訴模型「這些不是車」。

### 2. 手動標註約 50 張（10 分鐘）

```bash
python tools/label_dataset.py --dir data/toycar
```

| 按鍵 | 動作 |
|---|---|
| 拖曳 | 畫框 |
| 空白 / d | 存檔＋下一張 |
| **x** | **這張沒有目標**（存空標籤＝負樣本） |
| u / c | 復原 / 清空 |
| a | 上一張 |
| q | 離開（進度保留，可續標） |

標到 50 張左右即可停。

### 3. 預標註剩下的（自動，5~10 分鐘）

```bash
python tools/prelabel_dataset.py --dir data/toycar
```

用你標的 50 張訓一個快速模型，自動標註其餘影像。低於信心門檻的留空白，
不會亂塞框。

### 4. 快速修正預標結果（5 分鐘）

```bash
python tools/label_dataset.py --dir data/toycar
```

逐張看過：框對就按空白鍵、框錯按 `c` 清掉重畫、沒車按 `x`。
**修正既有框比從頭畫快 3~5 倍**。

### 5. 正式訓練

```bash
python tools/train_toycar.py --epochs 100
```

從既有權重接續訓練（transfer learning），保留原本對車輛形狀的認識。
增強設定針對此場景：`degrees=180`（車頭任意朝向）、`scale=0.6`（高度差異大）。

### 6. 套用

```bash
copy runs\toycar\weights\best.pt weights\toycar.pt
```

設定頁把「權重」改成 `weights/toycar.pt` → 按「重啟引擎」。

## 自動標註為什麼行不通（已實測）

試過兩種、都失敗：

| 方法 | 結果 |
|---|---|
| **顏色分割**（白車 vs 灰地板） | ❌ 框到紙箱上的白紙——場景有其他白色物體 |
| **移動偵測**（車會動、箱子不會） | ❌ 同樣框到白紙——相機非完全固定＋畫面有人走動 |

所以採用**人在迴圈**（步驟 2→3→4）：少量手工 → 模型預標 → 快速修正。

## 品管檢查

訓練前務必確認：

```bash
# 標註框畫回影像肉眼檢查（框的位置對不對）
python -c "..."   # 見 .tmpdiag/label_check.jpg 產生方式
```

要看的指標：
- 框大小是否合理（不該有 <20px 或佔滿畫面的框）
- 長寬比是否符合目標（車約 0.4~2.5）
- 正負樣本比例（建議 3:1 ~ 5:1）

## 換目標時

同一套流程可用於任何新目標（真車、特定車輛、其他物體）：
改 `collect_dataset.py --out data/<新目標>`，其餘步驟相同。
`train_toycar.py` 的 `--data` 指向新目錄即可。
